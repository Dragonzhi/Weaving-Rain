# 风雨音效制作与接入计划

日期：2026-10-14。最新执行为第9节远景雨声修整；第8节五差分接入已通过专项和完整回归，随后用户实机确认风基本合适、提出雨声突兀且过近。前文保留制作／技术历史。来源见[audio-sources.md](audio-sources.md)，最新检查见[rain-distance-review.json](rain-distance-review.json)，不把候选认可扩大为游戏内最终混音验收。用户明确先不接入Godot MCP。开发期直接Godot试玩，不默认导出新包。

## 1. 制作路线：混合素材，离线处理

建议风雨长循环优先选现成、许可明确的CC0环境素材；拨风短音、界面轻点和成果短音用脚本离线生成。播放时由GDScript根据真实天气调整音量和少量音色。该路线是本轮制作提案，具体听感先通过小样确认。

现成素材提供雨滴落地、空气流动的自然细节，裁剪、滤波和混音后统一为轻柔、干净的听感。短提示用脚本制作，容易控制起音、时长和音高，也便于保持同一套声音语言。全脚本合成风雨可行，但首轮不把纯噪声循环直接当成最终雨声；风底也可用滤波噪声制作候选，与现成风声一起试听。

这里的脚本生成发生在开发时，输出普通WAV文件；游戏运行时不执行Python、不逐样本合成、不按每个天气格建立播放器。

## 2. 声音风格与首轮清单

对应已确认的圆润大色块画风，音效采用柔和自然底声，操作短音轻、短、有呼吸感。强天气增加密度与低频，不单纯无限加大音量。成果像一两下轻水滴／木片音，损坏用较低、较短的提示。提示不盖过天气变化。

| 声音 | 制作方式 | 播放依据／作用 |
| --- | --- | --- |
| 持续风底 | 优先处理现成风声；另做滤波噪声候选 | 读取最终低空／云层空气速度；包含人工风、自然环流、背景风和冷风。撤人工源后实际残风仍有声 |
| 雨底 | 优先裁剪自然雨声，制作无缝循环 | 读取实际落地降雨 `ground_rain`／`total_rain_rate`；不拿云水或成雨进度当作下雨 |
| 雨滴细节 | 从雨声提取少量纹理，必要时离线合成补充 | 只随实际雨量混入；小雨较稀、大雨较密，不增加新的降雨事件 |
| 拨风／风源确认 | 离线合成短风切，配轻起落包络 | 有效拨风提交、成功放置风带／漩涡时响；预览和无拖动点击不响风切 |
| 界面／关闭反馈 | 离线生成轻点，同一音色小变化 | 原生按钮确实执行时触发；关闭只确认人工风源撤除，不代表残风或风暴消失 |
| 水够／保住／池满／损坏／结算 | 同一组离线短音，按含义变化 | 沿用真实状态；水够是轻提醒，安全完成是更明确回应，永久损坏一次，结果音在真实结算后播放 |

首轮不制作背景音乐、海浪、鸟鸣、雷电、语音或每秒倒数声。暖海系统增强主要通过已有真实风雨层表达，不另造一个脱离当前天气的“风暴音轨”。

## 3. 素材选择与加工

先准备风、雨各少量候选，保留来源和作者，按实际文件核对许可。只将最终使用的素材与加工版本放进 `assets/audio/`；候选及长原始录音留缓存。来源、许可、生成种子和加工步骤记录在一份音频来源文档中。

已查到的候选入口：[wind1](https://opengameart.org/content/wind1)、[Rain on Window Loop](https://opengameart.org/content/rain-on-window-loop)，页面均提供CC0选项。wind1作者说明是预先合成的风声，不能记成自然实录。尚未下载或试听；窗面雨的硬质敲击未必适合草地，不能仅凭许可选定音色。若下载需登录或素材不合适，换可直接获取的来源，或先用明确标注的离线合成占位，不将找素材变成接入阻塞。

加工顺序：挑干净片段→去掉直流偏移／明显风噪碰麦→适度滤掉刺耳频段→统一音量余量→制作首尾交叉渐变与无缝循环→在游戏实际音量下再试听。保留自然的缓慢起伏，避免过度降噪产生水声伪影。

循环先试12–24秒，短音约0.08–0.40秒，44.1或48kHz、16位WAV作为首轮交付格式。确保循环边界不爆音、短音有起落包络、不削波；最终时长按听感调整。脚本采用独立随机种子，重复生成相同素材，不接触天气随机数。

## 4. 游戏接入与调参

增加一个 `weather_audio.gd`，由main持有并绑定当前模拟；复用Godot原生 `AudioStreamPlayer` 和音频总线，分为风、雨、反馈再汇入Master。原生播放与总线能力见[AudioStreamPlayer](https://docs.godotengine.org/en/stable/classes/class_audiostreamplayer.html)、[Audio buses](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html)。

- 固定最多三层天气循环和两个短音声部。播放器与资源初始化一次，切图重新绑定，运行时不反复读文件或建立节点。
- 天气摘要约10Hz读取一次最新发布状态，当前帧平滑调整音量。风按最终空气速度，不按鼠标移动或云移动速度；厚云响应弱时，空气仍可能有较强风声。湿空气浓度不作为风声开关。
- 雨由真实释放速率控制，同时考虑画面中覆盖范围。小面积强雨仍须可听，不能只做全网格平均而被大片无雨区稀释。静止云或尚未释放雨水时不响雨声。
- 有效拨风短反馈可直接随已提交输入触发，避免等10Hz摘要造成起手迟钝；不逐鼠标事件播放。长拖动／按住续吹主要由持续风底承接，短音有冷却和声部上限。
- 一次状态变化只触发一次提醒。复用地块缺水、危险、确认、安全、永久损坏与蓄水完成入口；安全失去后恢复可再次回应，但加短冷却。绑定初始状态不响“刚刚完成”，刷新HUD不重播。
- 多块地同帧变化时合并提示，损坏／最终结果优先，避免多个提示叠成噪声。满目标倒数启动不播放最终胜利音；倒数失星取消仍按原规则，真正结算才响结果音。
- 首轮采用轻微左右声像，按可听风雨重心的屏幕位置平滑变化，偏移封顶；不使用逐格3D声源。重心／投影读取复用静态坐标和当前相机，窗口／镜头变化时更新，避免把世界x轴误当屏幕左右。

`configs/audio.tres`独立保存风／雨／反馈音量、天气映射强度、淡入淡出和短音冷却等少量调参；详细注明效果、单位及范围。音频与天气配置分开，保存后R／切图重读；F6仍只负责天气。坏字段保留上一有效音频设置并报字段。素材路径失效时提示且安静跳过该层，不中断玩法。

菜单只增加音效开关与总音量，常驻工具栏不扩大。用户偏好另存 `user://audio.cfg`，不改最高纪录／入门存档格式；开发测试使用隔离偏好文件。风、雨、反馈比例放资源配置，不在首轮菜单塞多个滑杆。

## 5. 生命周期

暂停时天气层短暂淡出后暂停播放，恢复后淡入并读取当前天气，不补播暂停期间的提醒；暂停菜单按钮仍可有轻反馈。失焦默认静音并丢弃未播短音，恢复不补响；只改变声音，不自行改变已有天气推进规则。

重试／切图停止旧短音与天气层，清事件历史，绑定新模拟后淡入。关闭人工风源只给关闭反馈，持续风底按真实残风自然减弱。结算天气层约0.6秒淡出，播放一次当前结果反馈；结果菜单操作仍有声音。退出释放音频资源。

总线留足叠加余量，常态混音目标峰值不高于约-6dBFS，轻限幅作为保护。音量为零或静音仍能正常操作与获得所有视觉反馈；声音不参与模拟、判定或评价。

## 6. 制作与验证顺序

1. **先试听素材。** 输出可直接播放的轻风／强风、小雨／大雨对照，以及一组操作／成果短音。标清现成加工、离线合成或占位；用户试听确定音色，再扩大接入。
2. **接真实风雨。** 验证无风、局部拨风、按住续吹、风带、漩涡、冷风、自然系统及弱／强雨的过渡。重点听关闭源后的残风与停雨后的退声。
3. **接短反馈与菜单。** 核对成功／拒绝放源、原生关闭按钮、水够但不安全、池满、永久损坏、满目标倒数取消及真实结算；检查暂停、失焦、重试、切图和偏好保存。
4. **开发期审阅。** 直接在固定Godot中听普通／热带完整过程，记录听感及相关性能；完成必要规则、输入和生命周期回归。不默认导出EXE、压缩包或复跑独立包烟测。

自动检查音频格式、循环边界／峰值、播放器上限、事件冷却与去重、生命周期、偏好隔离，以及音效开／关时相同输入下的天气、水量、评价一致。headless与文件指标只能证明技术条件，不能证明声音好听、设备实际出声或无听觉疲劳；这些用实机与用户试听确认。

普通检查先聚焦音频和关联输入；接入main暂停／结算／切图或菜单流程时，按项目要求补完整回归。短开／关对照记录主循环成本、帧时间、模拟推进及积累，不并行其他压力测试，不以降低模拟速度换音频表现；正式空闲长性能验收及V1／V6继续保留。

交付为可试听小样、少量最终音频及来源记录、可调音频资源、Godot内可试玩接入和实际验证记录。仅在用户要求独立试玩／外部交付或需要验证导入资源在导出包中的表现时再打包。

## 7. 首轮实施记录（历史，音色由第8节更新）

当前12份44.1kHz PCM素材共约5.6MB，三层循环／两声部固定；实际PCM帧数控制循环，导入不归一化、不压缩。风底17.4秒、雨底／细节21.4秒。风读最终低空及云层速度，不以水汽浓度开关；雨读可见区域`ground_rain`累计与峰值，云水／激活雨子集未实际释放时保持安静。强弱映射、层比例、过渡、冷却和声像封顶见`configs/audio.tres`注释。

菜单原生开关和滑杆只在展开时显示；总线限幅保护与轻声像，音量立即生效。滑动结束后0.25秒合并写入单独偏好，退出时保存尚待写入值，不改最高纪录。暂停短退声后暂停流，菜单轻点保留；失焦立即静音、丢弃漏过的状态提示，恢复不补播；R／切图清旧声部并重绑。记录按钮动作沿用已有稳定风源ID，关闭源仍可听到实际残风，预览和拒绝创建不响放源音。

两尺寸各53项音频／真实控件检查通过，包含真正跨循环端点、Native Master录音、配置失败回退、F6、独立偏好、真实放置／拒绝／关闭与残风、暂停／失焦、池满、倒数不响胜利，以及两个独立模拟逐字节一致。首次残风夹具只推进一个固定步，未达到现有0.06风显示／音频阈值，已改为真实建立风场后撤源；首次日志保留。完整脚本重跑后全部规则、编辑器、GPU、既有流程和五份路线比较通过；此后的偏好合并写入及极小风切门槛／滑杆反馈修整再由两尺寸53项与两份真实录音路线覆盖，不把早先测试称为最终全部代码的一次验证。

## 8. 按已确认试听接入动作差分与A密雨

用户先认可第三轮短拨／风场／A雨衔接，再提出频繁操作应有多个差分；第四轮五差分和连续拨动试听获明确认可，用户授权接入。现在16份素材约6.6MB，保持三天气循环／两短音声部。旧`brush.wav`及`rain_detail.wav`标识保留，分别成为第一条同源风差分和A密雨层；新增`brush_2`至`brush_5`，五份与确认候选逐字节相同，原按钮／成果短音不变。合成吹气短音和B雨不再使用。

输入增加只读`brush_motion(gesture_id,speed)`：合法按下生成本笔标识，有效路径仍沿原规则施风，同时传出按世界平面距离／时间计算的速度。鼠标按下不发音，第一次有效移动才选择一条；同一笔后续移动只更新目标音高，声音结束也不重播。松手后保留自然收尾。速度归一化沿用本局`stroke_speed_full`，播放倍率0.92–1.10、约0.06秒平滑，均为可调音频初值。

差分使用独立RandomNumberGenerator洗牌，五条每轮各用一次，轮次交界避免连续重复；不使用全局随机数。音频记录本笔即使静音／预算拒绝也不在后续移动补响。暂停、失焦清短音，恢复仍须新按下；R／切图清手势与差分袋。高优先反馈抢占声部时停止更新被替换的拨风音高，其他短音播放倍率恢复1，声音不更改模拟。

普通拨风风底为原幅25%；按住续吹、已放风源、自然系统或可见冷风出流使风场底声平滑展开，仍乘实际最终风速。撤源后约2秒时间常数退回轻风底，保留实际残风；没有实际气流仍静音。雨强继续只读真实`ground_rain`累计／峰值，在0.20–0.85归一化区间等功率从小雨过渡到A密雨，强雨不叠加放大的细滴噪声。门槛／幅度在`configs/audio.tres`，R／切图应用，F6不重置音频。

验证与真实视口录音结果在`audio-refinement-review.json`。本轮重新运行两尺寸各53项音频／生命周期检查，新增两尺寸各24项手势检查通过，覆盖鼠标静止、十笔十次、同笔音高追随／结束不重播、两轮差分、全局随机数隔离、静音中途恢复、轻／强雨层以及风场退声。完整检查一次连续通过，含编辑器、GPU显示、输入、结算和五份路线比较；当时手势专项为22项，其后补充的随机数／中途恢复两断言由两尺寸24项覆盖，运行时代码未再修改。

普通／热带真实鼠标满风纹路线分别45.15／35.4模拟秒，五份差分分别使用17–18／27–28次，A密雨峰值倍率均达到0.65，Master录音无削波。首份热带录音曾因后台失焦导致雨层为零，原录音及报告保留缓存；仅录音工具增加监听焦点恢复并单独补跑，生产失焦静音规则不改。补跑未再发生失焦，0次恢复，完整风雨与结算事件均有记录。该工具变更不宣称再次跑完完整检查。

## 9. 远景雨幕与独立起落

用户反馈风基本合适，雨开始突然且近处清脆雨滴与俯视远景不符。当前风／雨共用0.25秒时间常数，约0.75秒已到95%；小雨源保留的叶片／地面瞬态又突出近场。保留相同自然雨源，对两份雨声离线削弱高频和孤立峰值，不补回音量，避免单纯拉低总音量后近处“噼啪”仍在。风、五差分和成果等其余14份文件逐字节不变，保持三循环／两声部。

雨声分别使用`rain_attack_seconds=1.1`、`rain_release_seconds=0.9`时间常数：稳定目标约3.3秒进入95%，停雨约2.7秒退去95%，仍随真实ground_rain目标变化。风与声像保留0.25秒；暂停／结果继续0.15秒快速退声，失焦仍立即静音。两个新增字段校验0.1–5秒，R／切图应用；F6不改音频。时间是显示初值，不把雨声尾音当作继续落雨。
