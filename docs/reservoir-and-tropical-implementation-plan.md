# 下一阶段：蓄水区与热带风暴主题局

日期：2026-10-13。状态：用户授权后已实现，规则、编辑器和正常视口路线已验证；玩家体验与正式空闲性能验收待完成。实际结果见[验证记录](reservoir-tropical-review.json)及策划第38节。交付时间参考 [Jam路线建议](jam-delivery-roadmap.md)。

## 1. 本轮交付

新增蓄水区目标及一个热带天气主题局，复用现有拨风、风带、漩涡、地块形状、固定三星和结果流转。先用独立蓄水小样检查目标规则，再完成同一主题局中的借雨、蓄水、农田保护及收尾。

首版最多一处可编辑暖海域、一个自然天气系统，总目标仍为1–3处农田／蓄水区。先交付较弱热带系统的组织、增强和衰弱，云带与降雨来自实际数据。成熟台风的完整眼墙结构和更多主题局按小样结果评估，不把固定贴图或自动播放的阶段动画当作天气模拟。

维持Godot 4.7.2、Forward+／D3D12、64×56网格、0.5格距、开放缓冲和60Hz固定步。全局人工风手感、农田需求与成雨规则保留。龙卷风、避雨区、风暴潮、强风直接损坏、多层云和排水输水操作不纳入首版。

## 2. 蓄水区目标与评价

- 在现有 `WRPlotNeeds` 增加目标用途，缺省为农田；新增 `configs/plots/reservoir.tres`。复用 `target_water` 表示满蓄容量，沿用当前面积归一化单位，不标成真实立方米。首个容量拟用250作为可调测试初值，最终按实际接雨调节。
- 蓄水区位置、矩形／圆形／椭圆轮廓沿用地图的 `plots`、`plot_regions`、`plot_needs`，不另建平行目标数组。受雨区完整位于平坦陆地且不重叠；总目标数仍不扩展。
- 落雨按原 `rain_targets` 归属，蓄水区不会吸走邻区雨，也不抽走云水。存储量到容量封顶，超过容量的实际雨水计入独立 `overflow_water`；首版只记作离开蓄水区的水，不模拟漫灌相邻农田。
- 蓄满即完成，完成保持；溢流不损坏、不撤星，也不要求附近停雨。农田仍按缺水、危险、安全确认、安全和永久损坏判断。
- 增加一个共同的目标完成查询，供实际完成数、固定三星、倒数、结果和HUD使用；不以伪造农田安全计时实现蓄水区完成。蓄水区的雨不计作自身威胁，但仍可能落入附近农田的真实安全缓冲，布局与提示须反映这一点。
- 一田一池完成一个一星、全部完成三星；总目标更多时沿用已确认折算。全目标完成仍进入原满星倒数，农田失去安全取消倒数；蓄水区完成不因此丢失。时限、暂停、普通主动结算和水分不足结束沿原方向扩展。
- 结果显示“完成X/N个目标”，各行分别解释农田水量／安全与蓄水进度，不把满池说成适量安全田。沿用版本2最高星数，新地图用独立ID，不重写旧地图纪录。

## 3. 暖海域、补给与水分收支

地图增加可空的暖海域资源，保存中心、椭圆范围、初始供能与主题初始扰动；旧地图缺省关闭。属性面板、文本与地图编辑共用资源，不改普通图开局。

- 首版供能使用每个有效海格的0–1代理量，不宣称完整海温、海洋混合或气压模型。陆地格不蒸发，海域形状可沿海岸裁切；预览显示实际有效海格。
- 蒸发按实际固定步、当地供能和有限速率增加低空湿空气，并累计 `evaporated_water`。不直接增加云、降雨或目标水量。
- 强天气长期作用的格子逐渐降低供能，蒸发与对流支持随之减弱；首轮不加入供能恢复，R恢复地图初始值。供能阈值、蒸发速率与冷却速度全部配置化。
- 在指定的适合对流的暖湿海域，实际湿度足够、气流持续汇聚才启动初始对流；按转移量从humidity扣除、向cloud增加。后续组织化天气在有效供能和供给支持下维持抬升；弱化后回退，不因按下漩涡工具直接造云。
- 海域对流与原山坡、冷风抬升顺序处理剩余湿空气，每次转移有上限，避免同一份水重复转化。抬升反馈读取本步实际转移。
- 收支统一为 `initial_water + evaporated_water = 湿空气 + 总云水 + 各目标实际存水 + rain_lost + escaped_water + overflow_water`，rain仍是cloud子集，供能和冷空气不计水。目标面积倍率须还原实际水量。
- 只要仍有有效海域补给，就不宣称“当前储备不足，因此任何新目标都无法完成”。显示“海域仍在补给”，储备条只表示当前空气水量；补给全部停止后才恢复原保守不足判断。到时仍照常结算，不因补给存在无限延长。

## 4. 自然天气、环流与中心移动

自然天气独立于人工风源集合，不占两个工具名额，没有人工关闭按钮，也不按30秒删除。一个运行状态保存中心、移动速度、组织／强度及阶段；云、水汽和雨继续存在原网格中，不为风暴复制第二套水量。

### 组织与强度

在暖海域候选位置，持续对流、湿空气汇入与同向旋转结构共同建立组织度。单纯总水量高、瞬时强风或工具档位不触发阶段跳转。成熟后的维持与增强看实际供能和对流活动；离开有效供给、对流不足或组织被打散时逐渐衰弱，已有雨云继续释放储水。

将阶段作为连续组织／强度的解释，使用带回退余量的分界，避免标签来回跳。测试用“对流组织中／热带低压／风暴／衰弱中”，不把游戏世界速度直接换算为现实台风分级。旋向由主题环境配置，首图采用北半球气旋方向；两种人工漩涡操作保持原样。真实成因参考见策划第36节，首轮不新增科里奥利方程、垂直风切变层和气压求解器。

### 气流分工

- 保留原 `wind` 作为玩家风。增加背景环境风与自然天气贡献，组合后分别发布云层实际风和低空实际风；低空继续加入原自动冷风。
- 人工风仍同时影响低空与云层。自然天气允许低空向内汇入、云层形成旋转云带及适度展开，实际速度有配置上限和软边。
- 云响应继续考虑厚度与雨云阻力，cloud、rain、charge使用同一云速度搬运。白线与箭头读取最终实际速度；静止优化必须检查组合后的真实风，不能因玩家风为零跳过自然天气。
- 中心读取外围环境气流的加权平均，排除自身环流和仅作用低空的自动冷风。用有限速度、惯性和固定步积分移动；外围拨风／风带可以逐渐影响方向，中心不能直接抓取。
- 不瞬移或整体复制云雨来追中心，局部天气仍按实际气流搬运。中心移动与旋转速度分离；无环境引导时不会仅因自身旋转自行漂移。
- 中心、云、水汽可以离开编辑区及模拟边界，不夹回最外一排。域外停止相应施力，已有水分按原缓冲与出流计账，不清空整团天气换取消散。

## 5. 表现、配置与地图编辑

### 表现

蓄水区用简单池岸与蓝色水面，水位／填充随真实存量变化，满后保持。地块旁显示小容量条、“蓄水中／已蓄满”与容量，不套农田蓝黄红过量预警，不放阻挡输入的大面板。首版水池用占位几何，不改变地形高度场或引入水流模拟。

风暴沿实际水汽汇入形成弯曲、间断的厚云带，云的形状与雨区仍由网格驱动。保持现有平滑轮廓、四档色阶、云影、深度遮挡及CPU拾取的一致定义。首版不以遮罩硬挖风眼或把固定螺旋图案旋转；成熟结构应从实际数据与环流调试取得。

暖海域用克制的海面色调／流动提示显示供给，随供能减弱降低强调；暂停冻结动画。自然天气小中心标记和短状态说明穿透输入，范围仅按需显示，不增加风工具按钮。所有实际风继续产生白线，包括无湿空气处；48条白线、32个天气箭头和32步体积采样预算不增加。

### 配置和编辑

热带调参加入现有 `WeatherSettings` 独立文件的分组：蒸发与供能、对流条件、组织／衰弱、环流、引导速度。每项说明单位、有效范围、调大／调小的后果与生效时机，不更改原人工风默认值。

首轮新热带参数、目标容量、地图环境与初始扰动均在R／切图应用；F6保留原LIVE_FIELDS行为，不重置天气、水量、供能或中心。错误字段保留上一有效配置并报告具体位置。

编辑器复用当前目标增删与需求关联，撤销同步维护用途资源；增加暖海域位置／范围及初始扰动预览和手柄。保存与试玩重载同一资源，暖海域初始中心需在有效海域，目标仍按现有平地与重叠检查。

## 6. 两份可试玩资源

- `reservoir_lab`：一块普通田与一个蓄水区，不启用自然风暴，用原山坡／冷风路线独立核对接雨、满池、溢流与计星。
- `storm_coast`：同类混合目标与暖海域，开场预设较弱天气扰动和可见初始云作为主题局例外。初始云从该图初始湿空气预算转移，计入initial_water，不额外注水；普通图仍只从湿空气开局。预置天气只定义初始条件，后续增强、雨量、中心移动和衰弱均读取实际状态。

首图围绕借外围雨带、让较强雨覆盖水池、及时保护农田做闭环，不要求风暴消失才让满池计成果。时限先用180秒测试值，容量和布局按正常路线调整；不修改普通田阈值或新增必须使用风暴的计分条件。

另设正常纯湿空气起点的技术回放验证有条件对流及从扰动组织，不作为开发注入夹具。新图已加入测试局流转，最终关卡序按真实试玩确认；预设初云及首图阶段为已实施的小样初值。

## 7. 实现顺序与验收

1. 先完成目标用途、满蓄／溢流、共同完成查询、结果与蓄水小样，再做占位池岸水位。
2. 接通暖海域补给、供能减弱和海域对流，核对每步水分账及不足结束。
3. 接通自然天气组织、两层环流、外围引导与真实显示，尽早在主循环检查帧时间和推进。
4. 完成主题局与真实事件路线，再细调容量、布局和天气配置；不为通关注水、清雨或改农田阈值。

相关规则检查覆盖：满池前后、超容量溢流、不同面积、池雨不阻挡池成果但仍可威胁邻田、混合目标星数／失星倒数／时限／不足结束；海上蒸发计账、陆格不蒸发、无条件不成云、条件回退、关闭人工源仍有自然环流、断供不立即停雨、局部供能减弱、风暴旋转不导致自漂移、外围引导、四边角落出流、暂停／重试／F6与旧图回归。

场景检查包括资源保存／撤销／试玩、池岸和标签拾取、白线与真实云／低空速度、抬升反馈、遮挡、云边连续性。使用现有Godot检查框架与视口事件工具，不另加测试框架。

至少两条正常主题路线比较先蓄池／先浇田，争取真实满目标倒数；补一个农田损坏后池仍可完成的流程，并记录水量、蒸发、溢流、流失误差与操作。独立导出及真实玩家试玩核对看懂风暴、引导、移云和收尾，自动通过不代表体验获认可。

运行完整规则与既有回放。1920×1080主循环短诊断覆盖活跃风暴、两人工源、云雨与低空压力。正式空闲验收保留既有两图12项，并为主题图增加同协议6项，预热5秒、采样60秒；P95≤16.7ms、P99≤20ms、推进≥99%、剩余积累≤100ms。此前短测超标不可覆盖，按用户安排空闲复测，不能丢积累或改形状规避门槛。
