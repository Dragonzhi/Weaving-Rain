# 教学与正式关卡流程安排

2026-10-14。用户确认顺序为：**现有教学关 → 单田 → 双目标 → 风暴＋蓄水区**，并计划自行追加地图，使难度递进更平缓。

本文件记录已确认的编排方向。2026-10-15用户授权接入可调关序，当前使用`configs/campaign.tres`统一教学引用和正式地图列表，初始仅收录level01；其余地图由用户随后制作加入。地图制作与加入步骤见[新建关卡与编辑器指南](level-editor-guide.md#能选到不等于下一关会去)，执行范围见[编排实施计划](campaign-implementation-plan.md)。

## 四段体验

| 顺序 | 内容 | 想让玩家掌握什么 | 当前素材／边界 |
| --- | --- | --- | --- |
| 入口 | 水库分步教学 | 发现水汽可交互，迎坡成云、降雨和蓄满；不要求移云与安全收尾 | 独立configs/tutorial.tres，沿实际天气推进三步，容量另配 |
| 单田段 | 独立完成一次灌溉 | 在自由操作下安排造雨、雨量和收尾；可以重试优化 | 用户提供level01并已自行试玩，配置与技术路线另行核对，不直接改其布局 |
| 双目标段 | 分配云雨 | 轮流送雨、风带分工，再逐步引入不同需水量 | 可从旧双目标／需求小样复制，不直接视为正式关难度已合适 |
| 主题段 | 风暴＋蓄水区 | 利用持续供给的强雨，区分池的容错与农田的过量风险 | 复用已实现系统，地图可从storm_coast复制调整 |

每段可以有多张地图，不限定正式总关数。用户新增图先独立保存／试玩，再按体验插入；暂不把测试地图的旧标题、旧顺序直接转成正式关号。

## 当前运行流程

1. 首次进入水库教学，完成或跳过后进入`levels[0]`；已有“进入过自由局”偏好直接进入该首关。重看教学后返回此前的正式／开发地图。
2. 菜单“选关”按数组顺序列出关号、标题和最高风纹，不锁关。打开暂停并取消手势，返回恢复此前暂停状态；开始本关才重建天气。
3. 成功后“下一关”按配置前进；配置末项成功显示“本轮挑战完成”，返回选关。零风纹也可重试或选关，但不能借“下一关”推进。
4. 编辑器／开发运行的“开发地图”、原`--layout`／`--map`与临时试玩保留；自动发现不等于正式入列。旧测试图不占正式关号，不再用旧列表环回。
5. 编排在启动和打开正式选关时重读；R不重读关序，仍重读当前地图，F6仍只更新天气。无效修改保留上次有效列表和天气，首次加载失败明确提示并留在教学。最高纪录仍按地图ID保存，不改格式。

当前教学及level01的布局、时限、需水量和评级规则均未代改；后续只需编辑`campaign.tres`的资源数组安排关序。完整技术记录见[campaign-review.json](campaign-review.json)，不把流转检查的结果夹具视为真实通关路线或新玩家难度认可。

## 先行制作与验证

关卡可以先用现有编辑器独立制作，不依赖开始界面的新设计。建议另存新文件，保留现有回放基线；不用每张图单独导出游戏。

每关至少检查：正常开局、实际迎坡／冷风或暖海条件、各目标接雨、永久损坏后继续、计时结束、满目标倒数、安全状态失去后取消，以及一条可完整完成的路线。

本轮已接入口／结果／流转，并检查真实原生按钮、两尺寸和既有回放；通过范围与失败以记录为准。V1正式性能与V6历史异常继续保留；发布、平台上传和新包导出仍按原授权边界处理。
