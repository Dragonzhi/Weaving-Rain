# 新建关卡与编辑器实用指南

2026-10-15，按当前项目代码核对。使用固定 Godot 4.7.2，编辑器插件已在项目中启用。教学为独立单水库，正式编排使用campaign.tres，编辑和加入步骤见下文及[关卡流程安排](level-flow-plan.md)。完整参数表另见[地图编辑与调参](map-authoring.md)。

## 先做出第一张自己的地图

1. 在 Godot 打开本项目，打开 `res://scenes/map_editor.tscn`。
2. 在左侧场景树选中根节点 **MapAuthor**。右侧切到 **风织雨地图** 面板；如果没出现，检查“项目设置 → 插件”中地图插件是否启用。
3. 点击 **加载地图…**，选一份现有 `.tres` 作起点，见下面的模板表。
4. **先点“地图另存为…”再改布局**。例如保存为 `res://configs/maps/l01_first_rain.tres`。保存成功后操作的是新副本，避免把测试基线当成自己的草稿覆盖。
5. 点击 **打开地图属性**，填写 `title`（玩家看到的关名）、`hint`（简短目标提示）；普通关卡勾选 `star_level`，设置 `time_limit_seconds`。
6. 拖动山、地块、湿空气的手柄调整位置；用面板添加／删除对象。数值和资源关联在地图属性里修改。
7. 修正面板指出的无效区域，直到显示 **地图有效，可保存并试玩**。
8. 点击 **保存地图**，再点 **试玩当前地图**。用实际游戏镜头检查造云、送雨和安全收尾；停止运行后继续编辑。

不必为每张关卡新建场景或相机。一个地图 `.tres` 就保存岛形、山、目标、水汽与可选暖海，所有地图复用同一个运行场景。

| 想做什么 | 建议加载的起点 | 接下来改什么 |
| --- | --- | --- |
| 普通单田 | `configs/maps/standard.tres` | 删除一个地块；勾选 `star_level`。它原来是双目标练习资源，不是现成的单田正式关 |
| 双农田 | `configs/maps/standard.tres` 或 `needs_lab.tres` | 前者两田默认需求，后者普通田＋幼苗；调整两处与山、水汽的关系 |
| 农田＋蓄水区，无自然风暴 | `configs/maps/reservoir_lab.tres` | 保留山坡造雨，调整田与池的分工 |
| 风暴＋蓄水区 | `configs/maps/storm_coast.tres` | 已有暖海、初始扰动、一田一池，先改目标和湿空气位置 |
| 多山路线 | `configs/maps/ridges.tres` 或 `valleys.tres` | 调整迎坡路线；不要一开始同时增加山数、距离和缺水压力 |

以上资源都是现有测试／练习基线，不表示已确定正式关号。建议另存新文件，保留旧回放使用的地图。

## 修改现有教学关

教学现在有独立资源：

- 地图：`res://configs/tutorial.tres`，保存教学的岛、山、水汽、水库位置与形状。
- 容量：`res://configs/plots/tutorial_reservoir.tres`，当前 `target_water=100`，是可调整的入门初值；不改其他地图使用的250容量池。
- 分步提示逻辑：`res://scripts/onboarding.gd`，按实际抬升／云、降雨和水库蓄满推进，不给玩家凭空加水。

在地图面板点击“加载地图…”，从默认的 `configs/maps/` 返回上一级 `configs/`，选择 `tutorial.tres`。随后用相同手柄编辑，保持**一个蓄水区**，点击“保存地图”。建议先备份；如果另存成其他文件，还需在`configs/campaign.tres`的`Tutorial`中替换引用，保存并重启或打开正式选关重读，再重看入门。

“试玩当前地图”能验证这份布局的水汽、云雨和蓄水规则，但它以自由试玩模式运行，**不显示分步教学**。检查完整教学时，运行主场景后在菜单点击“重看入门”；开发启动也可用 `--fresh-guide` 忽略已看过教学的偏好。

运行中的教学按 R 会重新读取已保存地图及容量，从湿空气／空水库开始。F6只改天气手感，不重新生成教学地图。坏地图会提示具体字段并保留上一份有效教学配置。

新教学为“推水汽上山 → 成云降雨 → 填满水库”，蓄满即可完成，不要求移开雨云或等待安全，不计时、不保存风纹。之后的农田仍按适量和安全收尾规则。普通农田关并没有因此变成水库。

## 属性放在哪里，手柄能改什么

点击“打开地图属性”后，Godot 可能把 `plot_needs` 显示为 **Plot Needs**，`humidity_sources` 显示为 **Humidity Sources**；下面使用真实字段名，方便对照文本配置。要回到插件面板与手柄，重新选中 MapAuthor。

| 对象 | 可以直接拖动 | 在属性面板中调整 |
| --- | --- | --- |
| 岛 | 中心、长轴、短轴 | `shape`、`coast_variation`、`river_enabled` |
| 山 | 位置、半径、高度 | `mountains` 数组各项的 `position`、`radius`、`height` |
| 地块 A／B／C | 中心位置 | `plot_regions` 的形状／半轴；`plot_needs` 的目标类型与需求 |
| 湿空气 | 中心位置 | `humidity_sources` 的覆盖、浓度、衰减 |
| 暖海（已设置时） | 中心、两条半轴、初始扰动中心 | `warm_sea` 的供能、组织度、开场云和背景风 |

地图资源中的二维坐标 `(x, y)` 对应三维场景的水平 `(X, Z)`，不是高度。保持 MapAuthor 根节点的 Position／Rotation 为零、Scale 为一；通过地图属性或手柄改地图。

支持 Ctrl+Z 撤销、Ctrl+Shift+Z 重做。山与地块等数量变化使用插件按钮，避免手工改数组时把位置、形状、需求的对应关系弄错。

## 制作单田、双目标与不同需水量

### 目标数量和形状

当前地图支持 **1–3 个目标**，农田和蓄水区合计计算。在面板的地块下拉框选中目标，再用“添加地块（最多三处）”或“删除所选地块”。不能删除最后一个目标。

三个数组按相同顺序对应：

| 索引 | `plots` | `plot_regions` | `plot_needs` |
| --- | --- | --- | --- |
| 0 | A 的中心 | A 的形状 | A 的类型／需水量 |
| 1 | B 的中心 | B 的形状 | B 的类型／需水量 |
| 2 | C 的中心 | C 的形状 | C 的类型／需水量 |

展开 `plot_regions` 的对应项。空项使用默认矩形；需要自定义时新建 **WRPlotRegion**：

- `shape`：`rectangle` 矩形、`circle` 圆形、`ellipse` 椭圆。
- `half_axes`：矩形半边长／椭圆半轴，例如 `(1.5, 1.0)` 的矩形完整宽深为 `3×2`。圆形取 X 作半径。
- `(0, 0)` 表示继承全局默认尺寸；自定义的两个分量至少为 `0.5`。

形状影响实际接雨区域和面积换算，不仅是装饰。相同质量的雨落入更大的地块，换算水量更少；均匀降雨同时覆盖更大面积时，也会接到更多实际雨水。不要单凭外观面积推断难度，最终用试玩确认。

### 选择需求资源

在 `plot_needs` 的对应项拖入资源：

| 资源 | 当前用途 | 完成条件 |
| --- | --- | --- |
| `configs/plots/ordinary.tres` | 普通田，当前 100–150 | 至少100、没有超过150，附近危险天气解除并维持安全 |
| `configs/plots/seedling.tres` | 幼苗，当前 40–55 | 少雨即可够水，但过量余地小；仍需安全收尾 |
| `configs/plots/reservoir.tres` | 蓄水区，当前容量250 | 蓄满即完成，继续降雨允许溢流，不要求附近停雨 |
| 空项 | 继承全局天气配置 | 不是“取消这个目标” |

想为某关单独设需求，先把需求资源另存到新路径，例如 `configs/plots/l02_garden.tres`，再关联到该关。检查资源路径，避免直接修改仍被其他地图引用的 `ordinary.tres` 等共享预设。

农田 `target_water` 是够水线，`flood_water` 是过量上限，后者须更大；**超过**上限永久损坏，恰好相等尚未损坏。池容量使用 `target_water`，忽略农田的过量上限。`appearance` 只改植物表现。

当前每颗UI雨滴表达固定水量，数量／分组随需求变化；满雨滴只表示够水，不代表农田已经完成。

### 计时与评价

正式挑战地图勾选 `star_level`：至少一个目标完成即可获得通关评价，也可以继续争取全部；全完成后自动倒数结算。单田完成是满三枚风纹，双目标完成一个是一枚、两个是三枚；三目标完成一／二／三处为一／二／三枚。

`time_limit_seconds` 为1–3600秒，现有测试图多为180秒。先让路线成立，再收紧时间。到时只计已经完成的目标，农田仍在受威胁或安全确认未满都不算完成。

未勾选 `star_level` 是旧练习规则：须全部完成，任一农田过量会失败，地图时限不生效。它**不会自动变成带分步提示的教学关**；现有教学由独立入门模式驱动。

## 放置水汽和山，决定关卡怎样玩

湿空气来自 `humidity_sources`，当前普通地图只在开局生成一次：

| 参数 | 调整效果 |
| --- | --- |
| `position` | 改变取水位置；放在容易推向迎坡面的地方，入门更容易找到路线 |
| `spread` | 两方向的覆盖尺度；调大通常同时增加覆盖和总初始水汽，不只是把同一份水摊开 |
| `concentration` | 乘全局初始浓度；调高局部和总储水都更多，可能更易形成大雨和过量 |
| `falloff` | 从中心向外下降的程度；调大更集中、总量通常减少，调小覆盖更松散 |

多个源的湿度会叠加。近似关系为 `浓度 × exp(-归一化距离² × falloff)`，所以改变覆盖和衰减也会改水量预算。普通图没有持续补给，吹出边界的水不会自动回收。

山的 `radius` 是山脚半径，`height` 是高于平地的高度，手柄高度最高2.5。重叠山体取最高高度，不累加。实际坡度也由同一高度场决定：改变山高或宽度会改变迎坡抬升，不只是改外观。

制作第一份单田时，建议保留一座山、一个清楚的主要水汽团，目标放在云离开山坡后不远处的平地，让玩家能分别看清“造云”和“送雨”。这些是摆放建议，不是程序强制规则。

## 风暴＋蓄水区怎么配

最方便的是从 `storm_coast.tres` 另存，保留其 `warm_sea` 资源；普通关卡将 `warm_sea` 清空即可关闭该环境。不要仅删除开场水汽就以为关掉了暖海补给。

| 暖海参数 | 用途／设计影响 |
| --- | --- |
| `position`／`half_axes` | 暖海中心／半轴，海域整体须在24×20编辑区内；陆地部分不提供海面补给 |
| `initial_energy` | 0–1供能初值；高通常维持更久，0关闭该海域补给，不是真实海温 |
| `seed_position` | 初始自然系统中心，必须在暖海有效范围内且位于海上 |
| `seed_organization` | 开场组织度；0从未组织状态开始，非零也不保证后续一定增强 |
| `initial_cloud_fraction` | 开场把部分初始湿空气转为云，0–0.8；不是额外注入水分 |
| `background_wind` | 环境引导风，模长不超过2；可影响系统缓慢漂移，不等于内部旋转速度 |

自然天气不占人工风源名额，关闭风带／漩涡不能删掉它。暖海供能会减弱，首版不恢复。更细的蒸发／组织／环流系数在全局 `configs/weather.tres`，设计单关时先调本地图的位置与供能，避免改动所有关卡的共同手感。

建议让蓄水区承接一条较宽容的借雨路线，农田提供需要提前移云的取舍。先验证一田一池，再决定是否加入第三个目标。

## 保存、试玩，以及接入连续关卡

### 保存与重新载入

“保存地图”才会更新当前地图资源；“地图另存为…”生成新路径，并自动把 `id` 改成文件名主体。例如 `l01_first_rain.tres` 的标识为 `l01_first_rain`，标题可写中文。建议文件名用小写英文、数字和下划线。

保存场景与保存地图资源是不同操作，不要只保存 `map_editor.tscn`。设计不同关卡时用不同文件名／ID；最高纪录按ID保存，复用旧ID可能看到旧版最好成绩。

### 单独试玩

“试玩当前地图”会验证并保存一份临时副本到 `.godot/map-playtest.tres`，然后运行真实游戏。可以试玩尚未正式保存的编辑内容，但退出编辑器前仍须保存自己的地图。

- R：重试已启动的临时副本。编辑器里又改了布局，需要停止运行并重新点击“试玩当前地图”，R不会读取尚未重新导出的编辑内容。
- 地图、目标需求和时限按新局应用；全局手感配置可按原规则开发F6重读，F6不重新生成地图。
- 临时试玩不读取／写入正式风纹纪录或首次入门偏好。
- 编辑预览主要用来摆放与校验；云雨、水汽、雨滴与池岸的最终表现以真实试玩镜头为准。

保存到 `configs/maps/` 且标识与文件名一致后，在编辑器运行主场景，打开“菜单 → 开发地图”即可独立试玩；`--layout=地图ID`也保留。开发浏览自动发现地图，不决定正式关序。正式玩家从“选关”进入编排列表。

### “能选到”不等于“下一关会去”

正式顺序改由 **`configs/campaign.tres`** 配置，原脚本里的`LEVELS`已删除。操作如下：

1. 在Godot文件系统中选中`configs/campaign.tres`，在右侧属性面板展开`Levels`。
2. 把已保存、已独立试玩的地图`.tres`从文件系统拖入数组；也可增加数组大小，再把地图拖进新增空项。
3. 用数组项左侧拖动手柄调整顺序；删除数组项只移出编排，不删除地图文件。第一项就是教学结束或跳过后进入的关卡。
4. 在检查器的资源菜单中保存`campaign.tres`，回到正在运行的游戏，打开“菜单 → 选关”重读；或者重新运行主场景。F6和R不重读关序，避免重试时突然换关。R仍会重读当前地图自身的布局、需求等。
5. 核对选关里的关号和标题，并实际检查“下一关”。最后一关通过显示“本轮挑战完成”，按钮返回选关，不绕回旧测试图。

`Tutorial`引用教学地图，目前为`configs/tutorial.tres`，须保持单水库。它和`Levels`分开，不占正式关号，也不记录风纹。教学的容量、位置仍在原地图／需求资源里编辑。

当前正式数组依次收录用户制作的`level01`至`level09`，没有把旧测试图当正式关。实际内容从单池、双池逐步加入农田、多山与风暴，见[九关核对](level-content-review.md)；仍可增删和重排，不限定每段一关。文件名无需连续，关号来自数组顺序；地图标题来自地图的`title`，最高风纹仍按稳定`id`保存，调顺序不丢纪录。新增地图需要启用`star_level`才能走正式结果／下一关。按关限制工具尚未实现，当前各图均可使用拨风、风带与漩涡。

正式列表不能空，不能含空项、重复ID或无效地图；报错会指出`levels[n]`。错误修改保留上一有效列表及当前天气，修正保存后重新打开选关即可。选关不锁关，打开会暂停并取消正在拖动的风，返回恢复原暂停状态，点击“开始本关”才清空天气开新局。重看教学后会回到原来选中的地图。

## 校验报错与常见问题

| 现象 | 检查什么 |
| --- | --- |
| 没有手柄 | 选中 MapAuthor，而不是资源或预览网格；确认插件启用和3D视口手柄可见 |
| 提示受雨区不在平地 | 地块完整边缘须在岛内、山脚外，不是只看中心；缩小形状或把整个地块移向平地 |
| 提示目标重叠 | 检查圆／椭圆的实际受雨轮廓；使用面板增删以保持三个数组对应 |
| 提示山脚出岛／海岸越界 | 缩小山半径或移向岛内；岛屿实际起伏边缘也须留在X±12、Z±10内 |
| 保存／试玩不可用 | 先处理面板具体字段报错；无效地图会被拒绝保存／试玩 |
| 天空一直不成云 | 水汽需有真实迎坡或有效冷风汇聚；平地向屏幕上方划动不是抬升条件 |
| 新图不在正式选关里 | 另存地图不会自动加入正式关序；保存后拖入`configs/campaign.tres`的Levels数组，并重新打开选关 |
| 新图不在开发地图里 | 路径须为`configs/maps/*.tres`、WRMapDefinition资源，内部ID与文件名一致；重新打开开发地图或运行主场景 |
| 改一块田，别关也变了 | 检查是否改了共享需求资源或全局weather配置；另存独立需求再关联 |
| 编辑预览能摆出来，实际过不了 | 几何校验不判断水量预算、路线或难度，需要实际完整试玩 |

## 让自己追加的关卡形成平稳难度曲线

每张新图先只提高一个主要压力：运输距离、目标数量、怕涝程度、供水分布或时间。不要同时把水减少、目标移远、上限压窄、时限缩短；这样很难知道玩家卡在哪。

可以在已确认的四段之间插小关：

| 插入位置 | 适合验证的变化 |
| --- | --- |
| 教学后、普通单田段 | 仍一块田，仅稍改山与水汽方向，让玩家独立重复一次完整过程 |
| 单田到双目标之间 | 两处较近、相同需求，先学分配；再加入不同需水量或不同位置 |
| 双目标到风暴之间 | 一田一池但先无自然风暴，学会“池满仍可接雨”；之后再引入暖海系统 |

这些是候选关型，不是必须实现的额外机制。每张关记录关名／ID、想让玩家学什么、正常路线、最常见失败、成功用时、剩余时间和一次可行的完整完成过程。单靠自动校验通过或自己熟练操作，不能代表新玩家难度合适。
