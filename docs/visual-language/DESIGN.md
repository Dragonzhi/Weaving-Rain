# 风织雨视觉语言

日期：2026-10-13，更新2026-10-15。状态：方向及参考图已确认，对应游玩UI已接入；实际检查范围见[UI实施记录](../ui-review.json)。依据见[决定记录](design-contract.md)，完整步骤见[当前UI实施计划](../ui-implementation-plan.md)，简短交接见[实施交接](implementation-handoff.md)。场景与入口分别见其实施记录；最新原生入口见第10节。

## 1. Visual Theme & Atmosphere

延续已选云层参考：平滑外轮廓、少量分层色块、青色海面、灰绿土地和米白细线。游戏场景是视觉主体；界面用小符号、细线和少量米白底承载信息。图形采用Godot二维矢量绘制或SVG，云与天气继续由真实数据驱动。

用户确认：农田同尺寸雨滴表达固定水量；安全状态用小符号和简短悬浮文字；整局评价改为三枚可点亮的风纹奖章。线宽、尺寸、时长及每滴20单位均为本轮提议的显示初值，须在实机核对。

用户随后认可[三张概念图](reference-images.md)的UI方向，并认可其中云、地形、水库、田地的更强立体感。后续场景美术以几何厚度和分层明暗增强体积：云顶／云底受光关系、岛岸侧面和山体层次、低矮池岸／内壁与水面高差、田土薄厚与稀疏植株。保持平滑轮廓和少量色块，不增加写实纹理。云继续实时变形，参考图不作为固定云素材；具体性能预算和场景实现另行制定。

2026-10-14用户认可初版UI并同意推进场景风格化光照，随后授权在新分支执行。[场景实施计划](../scene-volume-implementation-plan.md)采用固定共用光向、约四档云色及两三档地面材料；代码已接入，实际检查见[实施记录](../scene-volume-review.json)，阅读与体积感仍待试玩。[三张场景概念](scene-reference-images.md)只说明光向和厚度，不取代原云形、地图或实时玩法。

## 2. Color

2026-10-14地面第二轮以用户重新指定的[整体图](scene-references/final-style-target.png)为最终风格目标：圆润大色块、清楚土台／池壁及柔和落地影。首轮云获得正面反馈，地面变化不足；本轮允许改变装饰田面／池岸标高，保持实际高度场、受雨与天气规则。见[第二轮计划](../ground-volume-implementation-plan.md)。

| 用途 | 基准颜色 | 附加识别方式 |
| --- | --- | --- |
| 普通文字／轮廓 | 深灰蓝 `#354e57` | 清晰字形、细描边 |
| 次要文字／空心图形 | 灰蓝 `#607b80` | 低权重信息、空轮廓 |
| 短提示底色 | 米白 `#f0f5e3` | 沿用轻底板，透明度按背景核对 |
| 累计接雨／池水位 | 灰青蓝 `#7aaebc` | 雨滴向上填充、池内水位 |
| 农田过量余量减少 | 柔黄 `#ddc775` | 只读 `plot_warning()`；黄色仍未损坏 |
| 永久损坏 | 珊瑚红 `#c76e60` | 固定叉号／破损符号，配“损坏” |
| 安全确认／完成 | 柔金 `#997940` | 进度环／完成勾号，区别于水量颜色 |
| 整局评价 | 同一柔金 | 奖章外轮廓内三条风纹，暗／亮表示0–3份 |

天气颜色沿用现有代码：白线是实际气流，湿空气移动为珊瑚色、冷空气为蓝色、云移动为浅白、实际抬升为金色。雨区淡蓝覆盖表达当前落雨，雨滴表达累计接雨。颜色不是温度，也不是唯一的状态线索。

场景明暗采用珍珠白迎光顶面、冷灰蓝转折与底面；保持环境底亮。云影采用低对比冷灰绿／灰蓝，实际雨区仍为独立淡蓝轮廓；接触影小而软。背光只说明朝向，不能单独冒充雨云或改变土地状态色。

风源力度计保留上红／中绿／下蓝三档，增加对应一／二／三道短刻线；颜色表示力度。天气箭头在场景里流动，危险符号固定在目标信息旁；相近色通过位置、形状与运动区分。

## 3. Typography

沿用现有中文系统字体与回退，不为这一轮引入外部字体。常驻目标仅显示A/B/C与必要用途标记；状态短词示例为“缺水”“移云”“确认安全”“已保住”“已蓄满”“损坏”。

初值：常驻文字12–14逻辑单位，悬浮说明12–14，结果正文14–16。实机读不清时先增加字重和背景对比，不增大整块信息面板。水量与阈值留悬停详情；结果页明确列数值和原因。

## 4. Spacing & Grid

沿用Godot逻辑画布和现有窗口缩放。间距按4／8／12逻辑单位组织，轮廓约1.5–2单位。雨滴初值12×18，间距4；状态符号单独留约20单位。

普通田100需求显示五滴，幼苗40显示两滴，不因需水不同放大图标。预计每滴20测试单位，填充顺序从左到右、每滴从下到上。非整倍数的末滴按余量容量填满，悬浮说明标明末滴需水量。

自定义高需求不能生成无限长图列；本轮暂定最多六个显示槽，超过时前五滴单独显示，末槽用明确“×N”的分组雨滴，详情说明组内容量与末滴余量。不得不加说明地改成固定数量的百分比图标。最终尺寸在实机核对。

## 5. Layout & Composition

目标信息继续跟随地块旁的现有屏幕锚点，优先位于地块下缘，避免互相覆盖或被工具栏挡住。常态去掉大水量卡片的视觉重量，保留标识、雨滴／水位及状态符号。

悬停目标或其小图形时展开一层简短浮字，类似二级信息，不打开另一个操作菜单。离开后收起；最多展开一处。状态变化短提示紧邻目标。所有显示信息穿透拨风；只有实际按钮、选择栏、展开菜单和结果操作区阻挡输入。

左上计时与储备、底部工具栏、风源关闭按钮保留现有组织。本轮统一颜色、图形和措辞，不扩成新常驻面板。风纹奖章用于关卡纪录、结果、当前评价，操作工具仍用工具图标。

## 6. Components

| 组件 | 常态表现 | 读取来源 |
| --- | --- | --- |
| 农田水量 | 同大空心雨滴逐滴填充，够水后蓝→黄，损坏立即红 | `water_for()`、`required_water()`、`plot_warning()`、永久损坏字段 |
| 蓄水区水量 | 小池形容器及水位；满后保持蓝色，允许溢流 | `is_reservoir()`、`plot_progress()`、`target_complete()` |
| 缺水 | 水滴轮廓／未填满；悬停说明差额 | `plot_status()`／目标需求 |
| 适量有危险 | 柔黄提醒符号；浮字“移云” | `plot_status() == danger` |
| 确认安全 | 小环读实际安全计时；悬停显示秒数 | `plot_status() == confirming`、`plot_safe_times / safe_seconds` |
| 已完成 | 实心完成勾号，短暂“已保住”／“已蓄满” | `target_complete()`；失去安全时即时撤掉 |
| 已损坏 | 红叉／破损轮廓，短暂“损坏” | 永久损坏状态 |
| 评价 | 三枚同形风纹奖章，按现有0–3评价点亮 | `earned_stars()`／`result_stars`／最高纪录 |

场景材料共用固定光向：云在已有可见表面估计受光，山体沿原法线分档，土侧边和池内壁增强厚度。首次小样不增加高成本体积自阴影；显示配置与天气配置分开。装饰不能更改地形高度场、云密度与厚度、目标轮廓或雨区的深度规则，细节见场景计划。

满雨滴只表示水够，不直接亮完成符号或奖章。农田填满后不追加多余雨滴；额外接雨通过预警颜色和悬浮“当前量／上限”表达。完成农田仍可能因天气变化失去安全，奖章按当前规则回退；蓄水区满后不回退。

玩家文案暂用“1枚风纹”“满风纹”“风纹评价”，逐目标结果仍说明实际保住数量。此为表达初稿，不新增“风力”“风能”等可消耗资源，也不改变计星规则。内部star字段、最高纪录版本与存档格式保持兼容。

## 7. Motion & Interaction

水量填充平滑过渡初值0.15–0.25秒，只改变显示。危险出现、永久损坏及完成标记撤回读实际状态即时处理，不能被插值拖延。安全环严格跟随真实计时，不用装饰动画伪造确认进度。

完成时轻亮一次，不连续弹跳；缺水／危险不无限闪烁。短文字沿用约1.2秒事件提示、悬停详情随悬停保持。避免从每块地同时飘出大段文字。风纹奖章点亮可错开约0.12秒，结算按钮从显示之初就可用，不等动画结束。

所有游戏反馈随暂停冻结；暂停期间仍可切换菜单和读取悬停说明。重试、切图清空旧提示。浮字不提交风、不改变手势参考面。白线、流动箭头、真实雨线和雨区保留现有行为与预算。

## 8. Voice & Brand

用动作和状态短词帮助决策：水够但有风险说“移云”，完成说“已保住”，池满说“已蓄满”。悬停补充一句原因，结果页完整说明。

危险、剩余时间和不足结束仍提供必要提示；减少常驻说明，不删除玩家完成操作所需的信息。“风纹”是成果评价，不是需要填充的操作能量。颜色图例和操作说明放在现有按需说明中。

## 9. Anti-patterns

- 不用雨滴满格直接表示目标完成；不把安全环当作成雨进度。
- 不把蓄水区溢流染成农田损坏红色；不把黄色说成已损坏。
- 不用星形、旋涡范围圈或工具按钮直接充当风纹奖章；奖章具备独立外轮廓。
- 不用全屏半透明大板承载地块日常信息；悬浮文字不能拦截天气操作。
- 不靠颜色独自区分强度、安全或损坏；不引入温度模拟含义。
- 不新增每滴节点、每格扫描或逐帧完整路径构建来画小图形；复用现有缓存与批量绘制。
- 不让状态动画掩盖真实危险、延迟损坏或取消满目标倒数；不修改天气参数来配合展示。
- 不将参考云图导入为固定游戏云；不复制参考图的装饰河流、地块数量和位置来改变当前地图。
- 不照搬新参考图的高云塔、细碎纹理、强投影或额外石块；阴影须让湿空气、冷空气和真实雨区仍可读。
- 不在每个视线采样点再做太阳光步进，不以减少原采样、丢模拟积累或改变天气形状换光照效果。

## 10. 主界面与选关方向（2026-10-15）

用户查看三版交互初稿后选定 **B · 风过群岛**。入口采用奶油底、居中标题与岛屿场景窗口，下方横向放置主要菜单；选关采用九宫格缩略图，配所选地图的大图、目标及开放工具。帮助和设置沿用同一套轻面板、深青文字与细风线。采用 B 整体方向，不混入 A 的左侧竖排菜单。

具体落地见[入口界面实施计划](../front-menu-implementation-plan.md)，原生页面已接入，实际检查见[审阅记录](../front-menu-review.json)，观感待试玩。

[交互稿](../../design-demos/menu-b.html)与[选择原话及边界](../../design-demos/direction-approved.md)作为后续实施依据。Godot 原生入口已按此接入，复用 campaign、最高风纹、教学和声音偏好，不另造关序或存档。背景场景保持实时程序天气，演示截图不作为固定游戏云素材；普通地面保持纯色。

## 11. 风雨主题转场（2026-10-16）

用户认可风掠＋云聚＋轻淡入组合并授权接入。主界面↔选关使用白色弧线和淡青风幕，约0.65秒；开始／换关与返回使用珍珠白、浅灰蓝分层云团，约0.85秒；设置、说明和暂停只用约0.18秒淡入。水纹候选不采用；不引入新天气符号或转场音效。原生绘制仍须保持平滑圆润，云幕仅为界面装饰。

取消手势后开始，遮挡中换场景，等目标画面就绪再揭幕；揭幕结束后才允许拨风与计时。设置提供本次运行的减少动态选项，改用约0.12秒淡入。实际检查与短性能见[转场记录](../theme-transition-review.json)，不能用HTML或短采样替代正式天气验收。


风掠修整：用户反馈单色过简后，采用灰蓝／薄荷／珍珠的连续色带、两层淡色外沿和13条错相流动白风线。外沿可透明，中段换页仍须全不透明；不得以叠加色彩破坏遮挡。见[本轮实测](../wind-sweep-review.json)，原0.65秒节奏保留，新观感待试玩。
