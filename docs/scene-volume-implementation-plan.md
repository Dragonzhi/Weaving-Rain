# 场景立体感实施计划：统一光向、云体明暗与材质厚度

日期：2026-10-14。状态：用户授权先提交基线、另开分支执行；基线为 `8f24ca7`，实施分支 `codex/scene-volume`。统一受光、云影、土侧边、池内壁与显示配置已接入，检查范围见[实施记录](scene-volume-review.json)。新场景待试玩反馈，概念图不表示运行效果或性能验收。

依据：[共用视觉规范](visual-language/DESIGN.md)、[场景参考图](visual-language/scene-reference-images.md)、策划§41–42。当前UI功能已接入，用户反馈“当前初版UI不错”；既有天气、UI、测试地图和存档作为基线。

首轮后用户反馈地面变化不足，并指定原整体图为最终风格目标。后续以[地面第二轮计划](ground-volume-implementation-plan.md)及[实际记录](ground-volume-review.json)为准；下文保留首轮范围，原“田顶不抬高／池沿0.41”等装饰限制已被第二轮替代，真实天气与高度场约束继续保留。

## 1. 本轮目标与范围

保持固定正交斜俯视、平滑轮廓与少量分层色块，通过共同光向、明暗和现有几何的厚度增强云、山、岛岸、农田与蓄水区。画面仍突出天气操作，不能让投影和装饰掩盖湿空气、冷空气、风线或实际雨区。

按顺序交付：先云＋山体小样，再云影与海岸，最后农田／水库细节。使用现有地图比较；不调整地图布局、云层高度／厚度定义、天气阈值、时限、目标需求和评价。不制作新UI、声音、昼夜循环、完整台风形态或新的天气机制。

图片中的凸起云瓣、石块数量、池形与位置只说明受光和材料，不逐项复制。单云层的实际可允许厚度继续由天气数据决定；不能增加固定球体或随机凹凸把云做得像概念画。

## 2. 当前实现与差距

| 当前入口 | 已有内容 | 需要完善 |
| --- | --- | --- |
| `shaders/cloud.gdshader` | 实时云水、同一连续表面、四档颜色、最多32步、深度遮挡 | 明暗主要随云水、雨水比例及上下位置变化，没有统一方向的迎光／背光 |
| `shaders/terrain.gdshader` | 按法线与固定方向计算三档明暗；同一云水场的淡地面云影 | 云与地面共享方向，云影的偏移、强弱和不同接收材质需统一 |
| `scripts/weather_view.gd` | 海岸已有侧面；池已有池岸和水位；农田、植物多用无光照纯色材质 | 充分利用现有几何，让土侧面、池内壁、叶面可辨，避免全场纯色 |
| `shaders/ocean.gdshader` | 少量装饰水纹及暖海供能颜色 | 保留供能提示，用少量材料层次承接岛岸与必要的弱云影 |

场景材料目前多为 `unshaded`，仅添加灯节点不会使现有云自动受光。继续用材质明确计算风格化明暗，不先将全部场景切到标准写实光照。

## 3. 共用光向与显示配置

- 一束固定的世界方向光，初值沿用地形现有 `normalize(Vector3(-0.6, 1.0, 0.3))`，通过当前相机核对参考图所示迎光关系；云、山、土、池岸统一读取。不给每类物体另设互相冲突的太阳方向。
- 明亮但不发光的顶面，较冷的转折面和底面；云约四档、地面材料两至三档。色阶边界保持窄且平滑，不增加纹理噪声。
- 环境底亮保留，让背光侧仍能读懂形状。首版不增加实时体积自阴影、全局照明、全屏环境遮蔽、镜面反射或泛光；几何遮挡与原深度关系保留。
- 需要跨材料调整的光向、底亮、云光照强度、云影／接触影强度和少量共用色板，集中为一个显示资源 `configs/scene_style.tres`，由 `scripts/scene_style.gd` 定义；不混入 `WeatherSettings` 或地图玩法资源。
- 参数说明调大／调小的视觉效果。方向须有限、非零并来自上方；强度有限且在0–1范围，色板不得缺项。坏字段保留上一有效显示配置并给出字段信息，首次无有效配置用默认值。初值沿用当前底色，再按实机审阅微调，不能预称最终平衡。
- 保存后重试／切图时重读显示资源；本轮不加新热键或游戏内面板，F6继续负责原天气手感。调显示不能重置或改写模拟字段。首次小样可直接用统一材质参数验证，再集中资源，避免先搭大框架。

## 4. 云：受光与天气状态分别表达

### 可见云体

在现有连续表面交点处估计朝向，结合共同光向得到受光程度，再映射到既有四档色板。只给已有的实时云形上色，不改变密度、透明度、轮廓阈值、垂直厚度或CPU拾取。

厚度和已激活雨水比例继续提供天气底色；方向明暗作为克制的调制。薄云背光也有浅灰蓝侧面，厚云没有激活降雨时仍不画雨；雨云更深，但白色风线、外轮廓与形变仍能辨认。不能仅因光向变化就让薄云看起来变成雨云。

优先复用现有表面／云场数据估计朝向，只在找到可见表面后计算一次。本轮不在32个视线采样点里再各走一套太阳光采样。当前B样条重建利用双线性合并只需四次纹理读取，不能为光照无意展开所有采样并大幅增费。表面导数或小尺寸数据缓存的具体选择由小样的稳定性和短测决定，只保留被验证的一种实现。

特别检查被拉长的薄边、两团云并合、分裂、开边界和云箱侧面。不能重新出现色阶随采样层跳动、灰蓝锯齿或明暗接缝；若表面朝向估计放大误差，先修估计或降低调制，而非增噪遮盖。

### 地面云影

复用同一份剩余云水、B样条重建与边缘渐隐，用共同光向把云影适度偏移到接收面。阴影随云移动和变薄同步变化；它是简化投影，不声称模拟云内完整遮光。

影色采用低对比的冷灰绿／灰蓝，薄云浅、厚云稍深，保持柔边，不能画纯黑大块。当前地形已有云影，改造这份入口而非另叠一层重复压暗。农田与池岸也接收同一云影；水面和模拟范围内海面采用更弱调制，范围外不新增读取。是否让海面接收完整投影先依据小样成本决定，若暂保留简化须明示。

云影表达遮光；淡蓝细轮廓雨区表达 `ground_rain`，二者不共用状态。云不下雨也有云影；移动光向改变影子不改变实际降雨范围、安全缓冲或UI。雨线仍从真实云底开始，并沿用云体遮挡和不写地面深度的规则。

## 5. 地面：用现有几何增强厚度

| 部位 | 实施内容 | 玩法边界 |
| --- | --- | --- |
| 山与地面 | 共用方向的两三档明暗，保留圆润山体；必要的山脚暗部克制铺开 | 不改高度场、坡度、顶面顶点位置或山数量，不为外观增加迎坡造云能力 |
| 岛岸 | 利用已有沙岸顶面与侧面，顶亮侧暗，简洁近岸浅色带 | 不重新生成海岸形状或扩大可操作陆地；海纹仍为装饰，不表示实际风 |
| 农田 | 在现有顶面下面补薄土侧边，低对比田垄只作材质；植物叶面两档色及小接触影 | 三种地块轮廓不变，侧边／小倒角向内组织；顶面标高不抬高，受雨范围与水量不变 |
| 蓄水区 | 补清楚现有池沿顶面、外侧与内壁，水面低于池沿，满池保留可见容器关系 | 保留原水位映射与容量，不挖新地形、不提高池岸改变操作，形状继续取WRPlotRegion |
| 植物与石块 | 优先材质分面，小而软的脚下接触影；稀疏现有植株 | 不新增大批节点、树木、围栏或建筑；植物生长、萎蔫读原状态 |

接触影首选少量固定几何或材质，随现有对象与暂停时钟更新；不为每株植被开启独立动态阴影系统。水纹复用显示时钟，暂停冻结。田地蓝黄红状态、池满蓝色及目标旁UI仍可读。

装饰材料的深度不能污染地面雨区重建：风线、雨线和抬升标记仍不写不透明深度。新增池内壁／土侧面须在真实视口核对雨区贴合，不得为了阴影让雨区投到云、风线或错误高度。

## 6. 实施顺序与阶段产物

| 步骤 | 产物 | 继续扩展前核对 |
| --- | --- | --- |
| 1 | 云＋单山同光向小样 | 薄云、厚云、雨云、长边和运动中色阶稳定；同一形状的朝向可读；短开销对照 |
| 2 | 共用显示资源、云影与岛岸 | 影子跟云同步且不冒充落雨，底色与暖海供能可读，边界一致 |
| 3 | 农田／植物与池岸／水面 | 原目标形状、水位、安全和损坏反馈一致，近处与正常镜头都能读懂厚度 |
| 4 | 多山、需水差异与热带整景 | 新旧输入、云雨遮挡、雨区、暂停、重试、切图无回退 |
| 5 | 当前少量实机图、检查记录与独立包 | 实际效果与概念区分，已知性能与波动仍公开，导出地图正确 |

前一步出现明显色阶断层或开销增加，先简化当前实现再铺下一类对象。首份可运行产物应有云＋山整体画面及三种云的并列实机对照，不只截漂亮静止厚云。

## 7. 验证

### 显示与规则分离

- 两种显示配置作用于相同输入和天气初值，核对湿空气、总云水、雨子集、成雨进度、冷空气、目标水量、供能与水分误差一致；显示配置只改变像素。
- CPU/GPU云形重建、云边拾取、开放渐隐与空区域优化保留。改变光向或照明强度不改变云占用轮廓、透明度及可拾取位置；优化开／关仍须保持同一图像。
- 云边拉长、收拢、并合、分裂和密集雨云的色阶连续；薄云背光与厚云未雨仍不产生雨线。
- 投影方向与山、土、池岸一致；雨区只取真实落雨，影区与雨区错开时仍能分辨。
- 农田三种形状及池内壁、满水、损坏、植株变化在1920×1080和1280×720审阅；雨滴、悬浮字和白色风线不被明暗吞没。

新增一份 `tests/test_scene_lighting.gd` GPU检查，覆盖光向改变确实改变受光面、云形／拾取和模拟字段不变、影子／雨区分离及暂停。沿用现有cloud-surface、render-fields、rain-layers、rain-area、HUD、风工具和资源检查；若旧颜色阈值检查需要适配新色板，保留连续轮廓所检查的性质，不删除失败检查来制造通过。

交付前运行完整规则／流程及五份路线比较，增加至少一份正常湿空气起步的热带真实鼠标路线。记录分段和复跑，不能把技术通关称为新玩家体验通过。最后重新导出并运行 `tests/smoke_export.ps1`，核对实际地图，更新zip与少量文档图。

### 性能

先对相同云／雨／冷风压力做旧视觉和新视觉的短对照，使用实际1920×1080、双人工源、箭头和雨区；记录CPU场景更新、GPU、P95／P99、长帧、模拟推进与结束积累。发展中的天气与真实事件时序不同，不能仅相减平均帧数声称精确光照成本。

当前UI短样热带拖动P95 18.499ms／P99 20.856ms已超门槛；因此不能把新视觉“接近旧版”写成性能验收通过。每一步报告新增开销，优先省采样和复用材料，不用降低60Hz推进、丢积累、减少原32步采样或改变云形换表现。

正式原两图12项及热带6项的5秒预热／60秒采样仍按用户安排留待空闲。门槛仍为P95≤16.7ms、P99≤20ms、模拟推进≥99%、结束积累≤100ms。原性能V1及原生异常／回放波动V6保留。
