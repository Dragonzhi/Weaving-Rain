# 当前UI实施计划：雨滴、悬浮状态与风纹评价

日期：2026-10-13，更新2026-10-14。状态：UI代码已接入，用户提醒即将没电关机，先保存检查点；完整回归与新版独立包尚未完成。源码基线 `5d208f8`。检查范围与剩余项见 [UI实施记录](ui-review.json)，接续入口见 [ui-resume.md](ui-resume.md)。

## 1. 依据与范围

用户确认同尺寸、固定水量雨滴，安全状态另用小符号和简短悬浮字，整局评价采用三枚风纹奖章；随后认可[游玩画面、目标状态、结算三张参考图](visual-language/reference-images.md)。视觉规范见[DESIGN.md](visual-language/DESIGN.md)，决定及显示初值见[设计记录](visual-language/design-contract.md)。

本轮完成当前游玩HUD、按需菜单和结果界面的共同图形、排版、文案与轻量动画。维持现有地图、天气、风操作、需求资源、安全判定、时限、评价及存档。新的开始／选关页面、声音与场景美术属于后续阶段。

云、地形、水库与田地的更强立体感已归档：后续通过云体分层明暗、岛岸厚度、池岸／水面高差、田土与植株层次提升；云仍实时变形，不采用固定图片。本轮UI不表示场景美术也已实现。

## 2. 游玩画面布局

- **左上：** 保留小标题、地图选择、倒计时和天气储备，整理为紧凑标题行＋储备行。长地图名截断、悬停查看完整名；较窄窗口允许标题行分成两行。地图选择用原生OptionButton，右上菜单用原生Button；文字与储备穿透输入。
- **顶部：** 正式评价测试局显示三枚小风纹奖章，表示本局当前 `earned_stars()`，不是最高纪录。0枚全暗，1／2／3枚按规则点亮；悬停简短说明当前与最佳。入门、普通练习和开发小样不凭空显示评价。
- **提示：** 现有短状态提示放在奖章下方，暂停、水分不足、满目标倒数及配置反馈保持必要可见性，不与标题或奖章互盖。
- **目标旁：** 常态仅A/B/C、雨滴行／水位容器及小状态符号，沿原地块屏幕锚点摆放。类型和准确数值收进浮字。避让其他目标、视口边缘、工具栏及已打开菜单，不扩大输入阻挡。
- **底部：** 沿用拨风／持续风／漩涡和天气提示控件，统一为细线图标、米白底与灰蓝字。保留明确名称、短操作说明和按需图例，不增加整块常驻说明板。
- **风源：** 真实剩余时间与关闭按钮按源数量出现。原生Button、稳定ID、名额、寿命及末段衰减不变；三档力度计保留红／绿／蓝并补刻线，与奖章区别。

## 3. 农田雨滴与池水位

### 固定水量雨滴

每滴暂取20个现有**面积归一化水量单位**，作为UI侧共用显示常量，不改天气配置或水分账本。普通田100需五滴，幼苗40需两滴，滴大小一致；从左到右、单滴从下到上填充。

设需求T、水量W，第j滴容量为 `min(20, T - 20*j)`，填充为 `(W - 20*j) / 容量` 夹在0–1。非整倍数末滴按实际余量容量填满：例如45需三滴，末滴只需5；浮字说明余量，不为图形修改需求。

常态最多六个雨滴显示槽。超过六滴时，前五滴保持单滴，末槽用明确“×N”的叠滴表示剩余需求；填充按该组的实际容量和水量计算，详情给组容量、组滴数及末滴余量。按显示槽绘制，不按总滴数创建图形；极长计数用紧凑数字，精确值留详情。这是大配置的显示回退，不改变每滴基准单位。

够水后保持满滴和总数；额外接雨通过 `plot_warning()` 从蓝渐黄。超过上限按永久损坏状态立即全红、出现红叉；恰等上限仍未损坏，停雨也不能让损坏变回蓝色。

### 蓄水区

池用独立小容器轮廓，按 `plot_progress()` 升水位；浮字显示容量和余量。蓄满显示蓝色满水和完成勾，继续承雨或溢流不黄／红，不播放农田安全环。

田与池都读现有目标接口，不把云水、当前雨强或雨区覆盖当累计水量。

## 4. 安全符号与悬浮字

| 实际状态 | 常态图形 | 按需短词 |
| --- | --- | --- |
| 缺水 | 未填满雨滴；无完成勾或危险三角 | 还差30 |
| 适量、有危险 | 满雨滴＋柔黄提醒符号 | 移云 |
| 确认安全 | 满雨滴＋真实安全进度环 | 确认安全 |
| 已保住 | 满雨滴＋完成勾 | 当前安全 |
| 永久损坏 | 红滴＋红叉 | 过量损坏 |
| 池蓄满 | 蓝色满容器＋完成勾 | 可继续承雨 |

状态读 `plot_status()` 与 `target_complete()`，安全环取真实 `plot_safe_times / safe_seconds`。缺水时即使下雨，也不能混用“适量但有危险”的提示。水量预警与天气风险保持各自含义，满水不等于完成。

浮字是**单层按需说明**：悬停目标或其小信息时展开准确水量、需求／上限和一句原因，最多一处，离开收起。状态变化则显示约1.2秒短词，沿用事件去重；持续降雨不反复弹字，安全失去后恢复可再提示，损坏优先。

事件提示和悬停重合时合并成一处，不叠出两块板。它不是可点击二级菜单，全部信息穿透拨风；精确数值与安全不足原因仍可查。

## 5. 风纹、菜单与结算

风纹奖章使用圆形外轮廓＋三条短流线，未获暗轮廓、已获柔金点亮，与工具图标、漩涡圈和力度计区别。当前评价、菜单入口、地图纪录、结果、提前结束及满目标倒数的玩家文案同步为风纹表达，例如“风纹评价 2/3”“以当前1枚风纹结束”。

原规则保持：零完成零枚，全完成三枚，未全完成且只完成一个一枚，其余两枚；实际完成数量另显。内部 `star_level`、`result_stars`、最高纪录字段和版本2不改，回放JSON保留原字段。旧纪录只替换显示，不新增另一份纪录或重复迁移。

结果页沿参考图使用米白居中小面板：结束原因、三枚奖章、逐目标结果、完成数量、最高纪录及原生重试／下一局按钮。宽度初值480–520逻辑单位，按实际1–3目标和文字换行调整高度。

每目标一组紧凑行，包含水量图形、用途、实际水量和准确状态。未得成果分别说明缺水、危险未解除、安全计时未满、永久损坏；池说明蓄满与溢流规则。失败原因在结果页直接可读，不仅靠悬停。

0成果不能显示成功标题；分别说明结束、到时或损失原因。结果按钮从面板显示之初可用，不等动画。

## 6. 工程与动画

主要修改 `scripts/game_hud.gd`。图形及显示换算需要复用时，可抽为一个 `scripts/hud_visuals.gd`；不建立新UI框架，不为每滴创建控件。Godot Theme统一原生Button／OptionButton的字体、选中、悬停、按下与禁用状态。雨滴、风纹、状态符号采用矢量绘制／SVG，不依赖字体中特殊字符。

轮廓与锚点沿用现有缓存；只处理1–3个目标，不新增天气网格扫描。显示只读模拟，动画不消费天气随机数。

初值：雨滴12×18、间距4、轮廓1.5–2、正文12–14逻辑单位，水量填充约0.2秒、奖章点亮错开约0.12秒。实机核对对比度和字号再调；不是最终验收数值。

危险、损坏、失去安全及满目标倒数取消即时更新，不等缓动。显示插值不参与完成判定。动画使用原暂停时钟：暂停冻结填充、反馈寿命和奖章，仍可打开菜单和读取浮字；重试／切图清空旧过渡与提示。

`blocks_wind()` 仅保留真实控件和原展开区域。关闭风源沿用Button信号：button_down锁定稳定ID，跨多帧pressed撤除对应源；重绘不能先隐藏后显示按钮而取消按下。

## 7. 执行顺序

| 步骤 | 产物 | 实际核对点 |
| --- | --- | --- |
| 1 | 共用图形、配色及水量显示换算 | 两／五滴、末滴、分组和池水位 |
| 2 | 目标锚点、状态符号和单层浮字 | 满水与安全分开，信息处可拨风 |
| 3 | 顶部／菜单风纹与结果 | 当前／最佳区分，旧纪录和失败原因准确 |
| 4 | 标题储备行、工具栏、源行统一样式 | 小窗口可读，工具和关闭按钮可操作 |
| 5 | 冻结动画、检查与正常路线 | 暂停／失焦／重试／流转保持原行为 |
| 6 | 少量实机图、文档和独立包 | 对照参考图阅读，并检查导出包 |

第一份可运行小样须呈现五种农田状态与池水位，不先只做漂亮结算页。生成图作方向，不直接当运行背景或云素材。

## 8. 验证与交付

- **显示边界：** 需求40／100／250、45末滴、超过六滴分组；零水、差一点够水、刚达标、接近和恰等过量上限、超过上限、永久损坏。回归检查实际显示换算，不给每个画线函数写镜像测试。
- **状态／评价：** 真实风险、安全计时、失去后再次保住、池满继续承雨、0–3风纹、1–6目标纯评价、满目标倒数及失星取消。
- **GPU／输入：** 更新紧凑反馈、目标反馈、HUD布局和风工具检查；实际截图核对雨滴／池状态和浮字。跨帧按钮点击、信息处开始／继续拨风、菜单、失焦、暂停、重试、切图均检查。
- **存档／流程：** 旧最高纪录与失败备份保护保留；正常需水差异和热带鼠标路线各一份。本轮改到结果及流转表现，运行完整规则／流程检查；中断、续跑或复跑按实际范围记录，不写成单次全通过。
- **阅读：** 1920×1080和1280×720检查1–3目标、长地图名、大需求、缺水／损坏／结算。截图坐标换算使用实际读回尺寸；满水与完成、风纹与工具、池蓝满水与农田黄红须能区分。
- **性能：** 短测记录UI更新、CPU／GPU、P95／P99、长帧、模拟推进和积累。正式原两图12项＋主题6项的5秒预热／60秒验收仍留到空闲；P95≤16.7ms、P99≤20ms、推进≥99%、结束积累≤100ms门槛不变。现有失败及原生异常不能因UI检查通过而关闭。

交付可试玩UI、检查记录、两尺寸少量实机图、更新文档及重新导出的本地Windows包。阅读体验和难度继续收集反馈；不自动包含声音、场景美术或TapTap上传。
