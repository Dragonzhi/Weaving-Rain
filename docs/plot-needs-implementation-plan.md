# 不同需水地块小样实施计划

日期：2026-10-12。状态：已实施，技术检查完成，用户完成本轮小样试玩并反馈没有问题；正式性能验收仍待空闲复测。本文件保留已批准的实施范围。讨论与实施结果见[策划第 31 节](cloud-weather-game-design-v0.1.md)、[验证记录](plot-needs-review.json)，当前进度见[任务看板](task-board.md)。

## 1. 目标与范围

用一张两地块测试图验证：同一套拨风、持续风和天气规则，面对不同需求时，玩家需要选择不同力度和停止时机。先做普通田与需水少、容易过量的幼苗地块。

本轮交付独立需求配置、统一地块判定、类型识别、蓝黄红预警、克制的植物反馈和正常开局回放。正式两关继续使用原需求，关卡时限、全局风力、云响应、成雨和安全规则沿用当前版本。

雨滴数量与正式造型属于未来 UI 美化。本轮先在现有紧凑水量条上验证相同的信息逻辑，让需求差异和过量风险可见；未来空心雨滴复用同一份填充和预警数据。旋转风、助手、声音和风主题评级不属于本轮。

## 2. 独立需求配置

新增 Godot Resource `scripts/plot_needs.gd`，保存类型标识、显示名、达标水量、过量上限和简单外观类型。需求资源只有配置数据，不保存本局接雨量、损坏或安全计时。

保存两个可直接编辑的外部资源：

| 文件 | 类型 | 达标量 | 过量上限 |
| --- | --- | ---: | ---: |
| `configs/plots/ordinary.tres` | 普通田 | 100 | 150 |
| `configs/plots/seedling.tres` | 幼苗 | 40 | 55 |

以上为小样初值。Godot 属性面板及文本编辑均可修改并保存。校验要求名称有效，数值有限且 `0 < 达标量 < 过量上限`；外观类型须为当前支持的值。错误信息指出资源路径与具体字段。

地图新增按地块顺序对应的 `plot_needs` 资源数组。位置、形状、需求各自负责一件事，同一种需求可供多块地复用。未指定或空项的地块沿用 `WeatherSettings.target_water / flood_water`，保持旧地图、入门、开发基线与既有回放的默认行为。

全局天气配置与需求配置分开。需求资源修改在 R 重试、重新进入地图或编辑器试玩时应用；F6 继续只应用现有即时天气字段，不在本局途中改变达标线和损坏线。重试使用已保存文件深度重读及验证；失败保留上一有效地图与需求，并提示具体原因。

## 3. 统一规则入口

模拟新增按地块查询的需求接口，如 `required_water(index)`、`flood_limit(index)` 和类型／名称查询。需求读取由模拟统一解析，HUD、渲染及开发控制器不自行重新加载配置或另算规则。

所有使用地块阈值的位置切换到统一查询：

- 缺水／适量／危险／确认安全／已保住／损坏状态。
- 安全维持计时、永久损坏、获星和结果原因。
- 首次够水反馈、移云提示及结果水量说明。
- `minimum_water_needed()` 与水分不足提前结束。
- 地面状态、植物长势和水量 UI。
- 开发回放选择待浇地块及切换输雨目标。

落雨覆盖与 `plot_water_scales` 的面积换算保留。配置需求使用现有归一化水量单位，不能把面积再乘一次。比较剩余天气水分时，每块缺水量仍须除以自己的换算倍率，还原实际水分；cloud 是总云水，rain 是其子集，不重复计账。

沿用现有边界判断：水量达到需求时算够水，超过过量上限才损坏；恰等于上限仍为黄色极限预警。损坏在本局不可恢复，重试清除。一块适量且安全的地块一颗星，达到水量不直接授星，安全条件与维持时间保持统一。

## 4. 地图编辑与测试图

新增独立资源 `configs/maps/needs_lab.tres`，名称“需水差异小样”，可从布局列表及现有地图编辑器打开。采用一座山、两块同面积的平坦地块、一份合理分布的初始湿空气；地块分别关联普通田和幼苗配置。开局只有湿空气。

两块面积相同用于先隔离需求差异；位置安排应允许先后输雨与已有云的转送，避免用过长搬运掩盖停止时机。具体坐标由现有地图资源与编辑校验确定，原正式地图不随小样改动。

小样沿用星级规则及 180 秒测试时限，至少一星可安全主动收尾。两地块不触发三星自动倒数；完整验证须主动安全结算两星。小样使用独立地图标识，不改变正式两关顺序，也不能把小样结果写成正式地图纪录。自动检查、`--fresh-guide` 与临时试玩继续隔离正式玩家存档。

Godot 属性面板可以为每块地选择需求资源。地图编辑器增删地块时，位置、形状和需求索引一起维护，并支持撤销／重做；移动只改位置。保存保留外部需求资源引用，另存和重载保持关联。编辑共享预设时打开对应 `.tres` 并明确保存；临时试玩使用配置快照，不回写预设。

## 5. 本轮 UI 与未来雨滴

地块旁保持小面板，显示字母、类型与当前量／达标量，例如 `A 普通田 · 0/100`、`B 幼苗 · 0/40`。悬停显示各自适量区间与状态原因，信息继续穿透拨风。不得恢复遮挡大片天气的大卡片。

本轮水量条按 `clamp(水量 / 达标量, 0, 1)` 填充：不足时蓝色，达到需求时填满。继续接雨不把填充画出条外，使用剩余容错预警：

```text
预警程度 = clamp((水量 - 达标量) / (过量上限 - 达标量), 0, 1)
未损坏颜色 = 蓝色与黄色按预警程度混合
损坏颜色 = 红色
```

达到需求后蓝色逐渐转黄，超过上限时立即变红，损坏后保持红色。红色切换不得被缓慢插值延迟。配合简短“缺水／够水待安全／已保住／损坏”状态文字，颜色不承担全部信息；有危险天气但未过量时，不显示红色损坏。

未来同大小、不同数量的空心雨滴，可按共同显示单位分滴填充。20 单位一滴、幼苗两滴／普通田五滴是当前建议，仍留给 UI 美化时确认。非整倍数的最后一滴表示剩余需求；规则读取配置，不从图标数反推。UI 数据提供接雨进度、预警程度和损坏状态，造型替换不重写模拟。多雨滴填满也只表示够水，安全确认继续独立。

HUD 控件继续使用 Godot 原生节点与信号；只赋最终显隐状态，不能重绘时先隐藏再显示。真实点击检查必须跨多帧按下与松开。

## 6. 植物表现

本轮采用简单几何作占位，普通田植株较高、较密，幼苗较矮、较疏；类型与地块形状独立，不能靠把幼苗田缩小来假装需求更低。

按方案默认做克制的长势反馈：植株从可见的小尺寸随接雨进度稍微长高、变饱满，达到需求后生长表现封顶；过量损坏转褐并下垂。安全尚未确认时仍可长满，危险与确认状态由现有地块反馈说明，不赋予额外生长分数或丰收机制。

复用现有几何与材质，按地块组织有限植株，避免为每片叶子新增节点或每帧重建网格。插值只改善显示，暂停冻结；渲染不写水量、不改变阈值与安全计时。正式作物造型和精细成长动画后续美术再做。

## 7. 实施顺序

1. 新增需求资源、两份配置、地图关联及校验，保证旧地图回退行为。
2. 接通统一需求查询，替换状态、损坏、结算、储备不足和开发控制器的全局读取。
3. 补地图编辑关联、增删撤销、保存重载和重试生效；建立两地块测试图。
4. 接通类型标记、独立水量区间、蓝黄红反馈与植物占位表现。
5. 做正常开局路线和实际视口验证，随后运行完整检查，更新审阅证据与看板。

## 8. 验证与交付

### 规则与配置

- 普通田与幼苗按各自阈值判定；需求边界、上限边界及上限以上判定一致。
- 共用需求资源不共用本局水量；不同面积的缺水估算、接雨和水分收支正确。
- 够水但危险／安全计时未满不得星；幼苗损坏后仍可保住普通田。
- 水分不足判断采用各自需求和面积倍率；已够水的存活地块不误报缺水。
- 需求文件保存、重读、重试生效与字段错误回退；F6 不改变当前需求。
- 未指定需求的旧地图与入门继续使用原默认行为；原路线不因这轮新增类型被重做平衡。

### 编辑与表现

- 地块需求选择、添加／删除、撤销／重做、另存、重载、临时试玩均保持关联。
- 当前量、需求、结果原因与状态查询一致；幼苗先够水、预警更快变黄。
- 未过量保持蓝到黄，损坏立即红；红色与危险天气状态不混淆。
- 信息面板允许拨风穿透，原生按钮的跨帧点击有效；标签在现有窗口尺寸下不遮挡主要操作区。
- 生长只反映接雨进度，长满不授星；损坏、重试、换图和暂停显示一致。

### 正常流程与性能

新增独立小样回放，分别验证普通田优先与幼苗优先，两条路线都从正常湿空气开局，只提交现有拨风或风带操作，不注水、清除天气或改阈值。两星在真实安全条件下主动结算；另测一块过量后继续挽救另一块。

补一次真实视口操作，覆盖滚轮选档、放带、跨帧按钮关闭、送雨、移云、安全收尾及结果。记录完成时间、操作数、最终水量、损坏与水分误差，不预先宣称不同田已更好玩或风带节省操作。

运行完整 `tests/run_checks.ps1` 及新增检查，保留旧回放。实机审阅缺水、够水未安全、黄色预警、红色损坏及结果截图；技术夹具与正常开局证据分开注明。对新增小样做 1920×1080 帧时间诊断，核对模拟推进与积累。

已有两关的正式性能验收仍是看板 V1 的待办，沿用用户空闲时单独复测的决定；这轮短样或截图不代替每项预热 5 秒、采样 60 秒的十二项验收，也不放宽 P95 ≤16.7 ms、P99 ≤20 ms 的门槛。

交付配置资源、测试图、编辑与规则入口、紧凑反馈、回放记录、审阅截图，以及更新后的 README、策划和任务看板。最终数值与植物表现由试玩反馈调整。
